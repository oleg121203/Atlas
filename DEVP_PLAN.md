### **DEV_PLAN Фаза 2: Інтелектуальний робочий процес та взаємодія**

**Головна мета:** Змусити всі існуючі системи працювати разом для виконання реальних завдань. Ми створимо основний робочий цикл агента, забезпечимо повний двосторонній зв'язок між ядром та UI, і активуємо механізми прийняття рішень та самовдосконалення.

#### **Завдання 2.1: Реалізація основного циклу агента (Agent Loop)**

* **Навіщо це потрібно:** Це "серцебиття" програми. Основний цикл буде отримувати завдання, приймати рішення про те, який інструмент використати, виконувати його та обробляти результат. Без цього циклу програма залишається пасивною.
* **Ключові кроки реалізації:**
    1.  **Створити `AgentLoopManager`:** Цей клас буде відповідати за безперервне виконання циклу в окремому потоці (`QThread`), щоб не блокувати UI.
    2.  **Підписатися на подію `TASK_CREATED`:** Коли користувач створює нове завдання в UI (`TasksWidget`), `AgentLoopManager` має його отримати.
    3.  **Інтеграція з `DecisionEngine`:** Усередині циклу для кожного кроку завдання викликати `DecisionEngine`, щоб визначити найкращий інструмент для виконання.
    4.  **Виконання через `ToolManager`:** Використати `ToolManager` для виконання обраного інструменту.
    5.  **Оновлення стану завдання:** Після виконання інструменту публікувати події `TASK_UPDATED` або `TASK_COMPLETED` з результатом.
* **Основні файли для модифікації:** `core/agents/agent_loop_manager.py` (новий), `core/intelligence/decision_engine.py`, `ui/tasks/tasks_widget.py`.

#### **Завдання 2.2: Повний двосторонній зв'язок між ядром та UI (UI-Core Data Binding)**

* **Навіщо це потрібно:** Щоб користувач бачив у реальному часі, що робить агент, і міг з цим взаємодіяти. UI має не просто віддавати команди, а й динамічно відображати кожен крок, думку та результат роботи ядра.
* **Ключові кроки реалізації:**
    1.  **`LogPanel`:** Підписати `LogPanel` на події `TOOL_EXECUTED`, `TOOL_ERROR`, `DECISION_MADE`, `AGENT_THOUGHT` (нова подія), щоб відображати детальний хід думок та дій агента.
    2.  **`TasksWidget`:** Реалізувати обробники подій `TASK_UPDATED`, щоб оновлювати статус, прогрес та результат завдання в списку.
    3.  **`ContextPanel`:** Підписати цей віджет на подію `CONTEXT_UPDATED` від `ContextEngine` та відображати ключові елементи поточного контексту агента (наприклад, активне вікно, вміст буфера обміну).
    4.  **Динамічне оновлення:** Переконатися, що всі оновлення UI відбуваються безпечно з основного потоку, використовуючи механізм сигналів та слотів Qt.
* **Основні файли для модифікації:** `ui/log_panel.py`, `ui/tasks/tasks_widget.py`, `ui/context/context_panel.py`, `core/events.py`.

#### **Завдання 2.3: Активація рушія самовдосконалення (`SelfImprovementEngine`)**

* **Навіщо це потрібно:** Щоб Atlas вчився на своїх діях. Після успішного чи невдалого виконання завдання система повинна аналізувати, що пішло так чи не так, і пропонувати шляхи для покращення (наприклад, створити новий воркфлоу, запропонувати новий інструмент).
* **Ключові кроки реалізації:**
    1.  **Збір даних:** Після завершення завдання (`TASK_COMPLETED` або `TASK_FAILED`) передавати всю історію кроків, рішень та результатів у `SelfImprovementEngine`.
    2.  **Аналіз та пропозиції:** `SelfImprovementEngine` має аналізувати ці дані. Якщо задача виконана неефективно, він може запропонувати створити новий воркфлоу. Якщо інструмент дав збій, він може запропонувати його змінити.
    3.  **Інтеграція з `SelfImprovementCenter` (UI):** Пропозиції від рушія мають з'являтися у віджеті `SelfImprovementCenter`, де користувач може їх прийняти або відхилити.
    4.  **Публікація події `IMPROVEMENT_SUGGESTED`:** `SelfImprovementEngine` має генерувати цю подію, на яку реагуватиме UI.
* **Основні файли для модифікації:** `core/intelligence/self_improvement_engine.py`, `ui/self_improvement_center.py`, `core/agents/agent_loop_manager.py`.

#### **Завдання 2.4: Реалізація контекстної обізнаності (`Context-Awareness`)**

* **Навіщо це потрібно:** Щоб рішення агента були релевантними поточному оточенню користувача. Агент повинен знати, яке вікно активне, що знаходиться в буфері обміну, які програми запущені тощо.
* **Ключові кроки реалізації:**
    1.  **Активне збирання контексту:** `ContextEngine` має періодично або за тригером (наприклад, зміна фокусу вікна) збирати інформацію про системне оточення за допомогою інструментів (`get_active_window_tool`, `clipboard_tool`).
    2.  **Зберігання контексту:** Зберігати зібрані дані у структурованому вигляді всередині `ContextEngine`.
    3.  **Надання контексту для `DecisionEngine`:** Перед кожним викликом `DecisionEngine` передавати до нього актуальний зріз контексту. Це дозволить LLM приймати значно більш обґрунтовані рішення.
    4.  **Публікація події `CONTEXT_UPDATED`:** Після кожного оновлення контексту генерувати подію, щоб UI (і `ContextPanel`) міг відобразити зміни.
* **Основні файли для модифікації:** `core/intelligence/context_engine.py`, `core/intelligence/decision_engine.py`, `tools/system_events_tool.py`.

#### **Завдання 2.5: Повноцінне управління та виконання робочих процесів (Workflows)**

* **Навіщо це потрібно:** Це дозволить автоматизувати рутинні, багатоетапні задачі. Користувач зможе один раз визначити послідовність дій, а потім запускати її однією командою.
* **Ключові кроки реалізації:**
    1.  **Збереження/Завантаження:** Реалізувати логіку збереження воркфлоу, створених у `WorkflowEditor`, у JSON-файл та їх завантаження.
    2.  **Інтеграція з `WorkflowManager`:** `WorkflowManager` має завантажувати доступні воркфлоу.
    3.  **Виконання воркфлоу:** Запуск воркфлоу має перетворювати його кроки на послідовність завдань для `AgentLoopManager`. `WorkflowManager` буде "диригентом", який послідовно передає завдання в основний цикл агента.
    4.  **Відображення в UI:** Забезпечити відображення доступних воркфлоу в UI, можливість їх запуску та відстеження прогресу виконання.
* **Основні файли для модифікації:** `core/workflow_manager.py`, `ui/workflows/workflow_editor.py`, `core/agents/agent_loop_manager.py`.
